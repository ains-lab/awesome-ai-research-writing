# Make AI Writing Better for Everyone

## 📖 왜 이 프로젝트를 만들었나요

당신이 같은 다듬기 프롬프트를 세 번째로 디버깅하는 사이, 옆 팀의 동료는 이미 준비된 템플릿으로 논문 세 편을 수정해 끝냈을지도 모릅니다.

학술 분야에서 prompt engineering은 점점 하나의 "보이지 않는 자원"이 되고 있습니다. 최상위 연구 그룹은 잘 정리된 템플릿 라이브러리를 갖추고 있지만, 많은 사람들은 여전히 처음부터 하나씩 시도하고 있습니다. 더 나아가 agent skills라는 신기술은 글쓰기를 더욱 강력하게 지원할 수 있지만, 아직 사용 진입장벽도 분명히 존재합니다.

이 저장소는 이런 격차를 줄이기 위해 만들었습니다. AI 연구 글쓰기에 필요한 실전 prompt와 agent skills를 한곳에 모아, 더 적은 시행착오로 더 좋은 글을 쓸 수 있도록 돕는 것이 목표입니다.

## 🎯 무엇을 제공하나요

우리는 [**MSRA**](https://www.microsoft.com/en-us/research/lab/microsoft-research-asia-zh-cn/), [**Seed**](https://seed.bytedance.com/zh/), [**SH AI Lab**](https://www.shlab.org.cn/) 등의 공개 자료와 실무 경험을 바탕으로, 연구 글쓰기에 바로 쓸 수 있는 도구들을 정리했습니다.

- **📝 Prompt 템플릿 모음**: 번역, 다듬기, 분석 등 다양한 상황에서 바로 사용할 수 있는 실전 prompt
- **🤖 Agent Skills**: 새롭게 주목받는 agent skills를 글쓰기에 적용하는 방법과, 글쓰기 관련 핵심 skill 정리
- **🎉 News**: 최근에는 arXiv 논문을 읽고 LaTeX 소스에서 번역 및 컴파일까지 지원하는 [**arxiv-translator-skill**](https://github.com/Leey21/arxiv-translator)도 소개합니다.

## ✨ 특징
- 🔬 **실전 중심**: 현업 연구자들의 실제 사용 시나리오를 반영
- 🚀 **바로 사용 가능**: 복사해서 즉시 활용할 수 있도록 구성
- 🤝 **지속적 업데이트**: 새로운 기법과 모범 사례를 계속 수집

**prompt 디버깅에 시간을 낭비하지 말고, 진짜 연구에 집중하세요.**

# Part I: 글쓰기 Prompt 모음

> 💡 **사용 방법**: 아래 Prompt는 채팅창에 그대로 복사해 대형 언어 모델과 함께 사용할 수 있습니다. 각 Prompt는 최적의 결과를 위해 신중하게 설계되었으니, 가능한 한 전체를 그대로 복사해 사용하세요.

## 중-영-latex

````markdown
# Role
당신은 최상급 연구 글쓰기 전문가이자 ICML/ICLR 등 주요 학회의 엄격한 리뷰어라는 두 가지 역할을 모두 갖춘 조력자입니다. 학술적 감각이 매우 뛰어나며, 논리적 허점과 언어적 결함을 매우 엄격하게 봅니다.

# Task
제가 제공하는【중국어 초안】을 번역하고 다듬어【영문 학술 논문 문단】으로 만들어 주세요.

# Constraints
1. 시각 및 배치:
   - 굵게, 기울임, 따옴표는 가급적 사용하지 마세요. 논문 인상을 해칠 수 있습니다.
   - LaTeX 원문은 깔끔하게 유지하고, 불필요한 형식 요소를 추가하지 마세요.

2. 스타일과 논리:
   - 논리는 엄밀해야 하고, 단어 선택은 정확하며, 표현은 간결하고 자연스러워야 합니다. 가능한 한 흔한 단어를 사용하고 어려운 단어는 피하세요.
   - 긴 대시(—)는 가급적 쓰지 말고, 대신 관계절이나 동격 구조를 사용하세요.
   - \item 목록은 사용하지 말고, 반드시 이어지는 문단 형태로 작성하세요.
   - "AI 느낌"을 없애고, 기계적인 연결어의 나열을 피하세요.

3. 시제 규범:
   - 방법, 구조, 실험 결론은 모두 현재 시제로 쓰세요.
   - 특정한 역사적 사건을 명시적으로 언급할 때만 과거 시제를 사용하세요.

4. 출력 형식:
   - Part 1 [LaTeX]: 번역된 영어 내용만 출력하세요(LaTeX 형식).
     * 언어는 반드시 영어여야 합니다.
     * 특수 문자는 반드시 이스케이프하세요. 예: `95%` → `95\%`, `model_v1` → `model\_v1`, `R&D` → `R\&D`.
     * 수식은 원형 그대로 유지하세요($ 기호 보존).
   - Part 2 [Translation]: 원문의 중국어 직역을 함께 제시해 의미를 대조할 수 있게 하세요.
   - 위 두 부분 외에는 어떤 추가 설명도 출력하지 마세요.

# Execution Protocol
최종 출력 전에 반드시 내부적으로 자기 점검을 수행하세요:
1. 리뷰어 관점: 가장 까다로운 Reviewer라고 가정하고, 과도한 형식, 논리 점프, 미번역된 중국어가 없는지 확인하세요.
2. 즉시 수정: 발견된 문제는 바로 고쳐서, 최종 결과가 엄밀하고 깔끔하며 완전한 영어가 되도록 하세요.

# Input
[여기에 중국어 초안을 붙여 넣으세요]
````

## 영-중-latex

````markdown
# Role
당신은 컴퓨터과학 분야의 숙련된 학술 번역가입니다. 복잡한 영어 논문 문단을 연구자가 빠르게 이해할 수 있도록 돕는 것이 임무입니다.

# Task
제가 제공하는【영문 LaTeX 코드 조각】을 자연스럽고 읽기 쉬운【중국어 텍스트】로 번역해 주세요.

# Constraints
1. 문법 정리:
   - 인용과 라벨은 무시하세요. `\cite{...}`, `\ref{...}`, `\label{...}` 등 읽기 방해 요소는 모두 삭제하고, 남기거나 번역하지 마세요.
   - 서식 명령 추출: `\textbf{text}`, `\emph{text}` 같은 장식 명령은 바깥의 LaTeX 형식은 무시하고, 중괄호 안의 `text`만 번역하세요.
   - 수식 자연화: LaTeX 수식은 읽기 쉬운 자연어 설명 또는 일반 텍스트 기호로 바꾸세요(예: `$lpha$`를 alpha로, `\frac{a}{b}`를 a나누기b로).

2. 번역 원칙:
   - 원문에 엄격히 대응하는 직역을 하세요. 윤문, 재작성, 논리 최적화는 하지 마세요.
   - 중국어 어순은 가능한 한 영어 원문 구조를 유지해야 합니다.
   - 원문에 문법 오류나 어색한 표현이 있더라도 번역에서 그대로 반영하고, 임의로 고치지 마세요.

3. 출력 형식:
   - 번역된 순수 중국어 문단만 출력하세요.
   - LaTeX 코드(수식 문법 포함)는 출력하지 마세요.

# Input
[여기에 영문 LaTeX 코드 붙여넣기]
````

## 중-영-word

````markdown
# Role
당신은 ICML/ICLR/NeurIPS/ACL 등 주요 학회의 관점을 모두 이해하는, 연구 글쓰기 전문가이자 엄격한 리뷰어입니다. 논리적 허점과 언어적 불완전성에 매우 민감합니다.

# Task
제가 제공하는【중국어 초안】을 Word 편집에 적합한【영문 학술 논문 문단】으로 번역하고 다듬어 주세요.

# Constraints
1. 시각 및 배치:
   - Markdown 문법(예: `###` 제목, `**` 굵게, `*` 기울임, `>` 인용, ``` 코드 블록 등)은 절대 사용하지 마세요.
   - Word에 바로 복사해 붙여넣을 수 있도록 순수 텍스트만 출력하세요.
   - 따옴표는 가능한 한 적게 사용하세요.

2. 스타일과 논리:
   - 논리는 엄밀해야 하고, 단어 선택은 정확하며, 표현은 간결하고 자연스러워야 합니다. 흔한 단어를 우선 사용하고, 드문 단어는 피하세요.
   - 긴 대시(—)는 가급적 피하고, 대신 관계절이나 동격 구조를 사용하세요.

3. 시제 규범:
   - 방법, 구조, 실험 결론은 모두 현재 시제로 쓰세요.
   - 특정한 역사적 사건을 명시적으로 언급할 때만 과거 시제를 사용하세요.

4. 출력 형식:
   - Part 1 [English Draft]: 번역된 영어 내용만 출력하세요.
     * 언어는 반드시 영어여야 합니다.
     * 기호 규칙: 95%, model_v1, R&D 같은 표준 텍스트 기호를 그대로 출력하고, LaTeX식 이스케이프는 하지 마세요.
     * 수식 보존: Word는 수학 텍스트를 직접 변환할 수 있으므로, 원문 수식 표기를 유지하세요. 예를 들어 $ 기호로 수식 범위를 유지하되, \because, \therefore 등의 수학적 인과 표기도 그대로 둘 수 있습니다.
   - Part 2 [Translation]: 원문의 중국어 직역을 함께 제시해 의미를 대조할 수 있게 하세요.
   - 위 두 부분 외에는 어떤 추가 설명, 접두어, 해설도 출력하지 마세요.

# Execution Protocol
최종 출력 전에 반드시 내부적으로 자기 점검을 수행하세요:
1. 리뷰어 관점: 가장 까다로운 Reviewer라고 가정하고, 과도한 형식, 깨진 포맷, 논리 점프, 미번역된 중국어가 없는지 확인하세요.
2. 즉시 수정: 발견된 문제는 바로 고쳐서, 최종 결과가 엄밀하고 깨끗하며 완전한 영어가 되도록 하세요.

# Input

## 중-중-word

이 prompt는 Word로 중국어 논문을 작성하는 상황을 대상으로 하며, LaTeX 환경과 비교해 맞춤 조정되었습니다.

````markdown
# Role
당신은 중국 학술지(예: 《计算机学报》、《软件学报》)와 최고 학회의 중국어 심사 관행을 모두 이해하는 숙련된 중국어 학술 편집자입니다. 파편적인 메모를 학술 규범에 맞는 문단으로 재구성하는 데 뛰어납니다.

# Task
제가 제공하는【중국어 초안】을 읽고, 이를 논리적으로 이어지고 중국 학술 규범에 맞는【논문 본문 문단】으로 다시 작성해 주세요.

# Constraints
1. 형식 및 배치(Word 적합):
   - 순수한 텍스트만 출력하세요. Markdown 굵게, 기울임, 제목 기호는 절대 사용하지 마세요.
   - 문장 부호는 중국어 전각 기호（，。；：“”）를 엄격히 사용하고, 수학 기호나 영어 용어 주변에는 적절한 공백을 유지하세요.

2. 논리와 구조(핵심 임무):
   - 논리 재구성: 문장을 기계적으로 다듬지 말고, 먼저 입력의 핵심 논리를 파악한 뒤 느슨한 문장을 다시 연결하세요. 목록은 반드시 연결된 문단으로 바꾸세요.
   - 핵심 집중: “한 문단 한 핵심 주제” 원칙을 따르세요. 문단 내 모든 문장은 같은 주제를 위해 봉사해야 하며, 여러 주제가 섞이지 않도록 하세요.
   - 자연스러운 흐름: 내용의 성격에 따라 개요에서 세부로, 원인에서 결과로, 혹은 시간 순으로 배열하세요. 문장과 문장 사이는 의미에 기반해 자연스럽게 이어져야 합니다.

3. 문체:
   - 매우 격식 있게: 구어체를 문어체로 바꾸세요(예: “不管是A还是B”는 “无论A抑或B”로, “效果变好了”는 “性能显著提升”으로).
   - 객관적 중립: 감정이 섞이지 않은 객관적 서술을 사용하세요.
   - 용어 규범: Transformer, CNN, Few-shot 같은 핵심 기술 용어는 그대로 유지하고, 업계에서 통용되는 영어 용어를 억지로 번역하지 마세요.

4. 출력 형식:
   - Part 1 [Refined Text]: 다시 쓴 중국어 문단.
   - Part 2 [Logic flow]: 재구성의 핵심을 간단히 설명하세요(예: 중심 문장을 추출하고, 중복 설명을 합치고, 서술 순서를 조정함).
   - 위 두 부분 외에는 어떤 추가 설명도 출력하지 마세요.

# Execution Protocol
출력 전에 다음을 점검하세요:
1. 이 표현이 고품질 중국어 핵심 학술지 논문처럼 보이는가?
2. 구어체 흔적이 남아 있는가?
3. Markdown 형식 기호가 남아 있는가?
4. Word에 복사했을 때 거슬리는 형식 기호가 있는가? 있다면 즉시 삭제하세요.

# Input
[여기에 중국어 초안, 흩어진 생각 또는 요점을 붙여 넣으세요]
````

## 축약

````markdown
# Role
당신은 간결성에 특화된 최상급 학술 편집자입니다. 핵심 정보는 하나도 잃지 않으면서 문장 구조를 다듬어 길이를 조금 줄이는 것이 강점입니다.

# Task
제가 제공하는【영문 LaTeX 코드 조각】을 약간 축약해 주세요.

추천하기 전에 아래 차트 유형을 우선 참고하여, 현재 데이터에 가장 정확한 것 하나 또는 둘을 고르세요:

수치 및 성능 비교형
1. 세로 그룹 막대그래프: SOTA 비교의 가장 표준적인 방식입니다. 비교 항목 수가 적당하고 라벨이 짧을 때 적합합니다.

데이터 관계 및 행렬 시각화형

통계 분포 및 구성형
14. 바이올린 플롯: 박스플롯보다 한 단계 발전된 선택입니다. 이중봉 분포 같은 확률 밀도 형태를 직관적으로 보여 주며, 통계적으로 더 엄밀해 보입니다.
15. 박스플롯: 여러 집단의 분포 범위, 중앙값, 이상치를 보여 주는 데 사용합니다.

복합 배치형
17. 이중 Y축 그래프: 한 그림에서 단위가 전혀 다른 두 변수를 동시에 보여 줄 때 사용합니다. 예: 왼쪽 축은 정확도, 오른쪽 축은 메모리 사용량.

19. 패싯 그리드: 비교 변수가 너무 많아 한 장이 복잡할 때, 여러 작은 그림을 격자 형태로 나눠 그리고 축을 공유합니다.

## Skills 설정

아래 설명은 **OpenSkills** 생태계를 기준으로 합니다. OpenSkills는 **범용 Skills 로딩/관리 방식**을 제공하여, Cursor 같은 AI coding agent가 `SKILL.md`를 핵심으로 하는 skill 패키지를 읽고 사용할 수 있게 합니다.

### 1) 선행 의존성

OpenSkills는 npm으로 배포되며 GitHub에서 skills 저장소를 가져오므로, 다음을 준비하는 것이 좋습니다:
- Node.js 20.6+ (npm 포함)
- Git

### 2) OpenSkills 설치/실행

OpenSkills는 `npx`로 바로 실행할 수 있습니다:

```bash
npx openskills --version
```

여러 프로젝트에서 재사용하려면 전역 설치도 가능합니다:

```bash
npm i -g openskills
openskills --version
```

### 3) Skills 한 번에 설치하기

OpenSkills는 GitHub 저장소에서 Skills를 직접 설치하고, 기본 디렉터리(보통 프로젝트 내부 `./.claude/skills/`)에 자동 배치합니다. Cursor는 `.claude/skills/`와 `.cursor/skills/`...

아래는 두 개의 상위 저장소를 예시로 보여 주는 설치 방법입니다:

```bash
# research 관련: zechenzhangAGI/AI-research-SKILLs
npx openskills install zechenzhangAGI/AI-research-SKILLs

# Anthropic 공식 skills
npx openskills install anthropics/skills
```

실행하면 OpenSkills가 인터랙티브 선택창을 띄워 필요한 Skill만 고를 수 있게 합니다(기본값은 전체 설치)

### 4) Cursor에서 Skills 확인 및 사용하기

Skills가 `.claude/skills/`에 설치되면, Cursor는 시작 시 이를 자동으로 발견해 Agent가 사용하도록 제공합니다. 다음 방식으로 확인하는 것이 좋습니다:

- **설치 확인**: `npx openskills list`로 대상 skills가 보이는지 확인
- **Cursor Settings에서 확인**: Cursor Settings를 열고 **Rules, Skills, Subagents**로 들어가 **Skills** 영역에 감지된 skills가 보이는지 확인
- **대화에서 수동 호출**: Agent Chat에서 `/`를 입력해 skill 이름을 검색하고 수동 삽입
- **대화에서 자연스럽게 유도**: 예를 들어 “회의 템플릿으로 새 초안 만들기”, “booktabs 표 작성하기”처럼 skill에 명확히 대응하는 요구를 하면, 동작이 Skill 문서와 일치하는지 통해 설정 성공 여부를 확인할 수 있습니다.

설정이 끝나면 복잡한 prompt를 외울 필요 없이, 대화에서 “무엇을 할지”와 “이미 가진 정보”만 명확히 말하면 됩니다. 예를 들어 연구 repo 경로와 목표 학회를 제공하고 “이 repo로 ICLR 2026 형식의 논문을 써 달라”고 요청할 수 있습니다.
